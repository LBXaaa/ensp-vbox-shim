# 环境诊断与修复:分档、范围与验证

本文记录 `环境检查.bat` 的设计规则与验证范围。用法见 [installer/README.md](../installer/README.md),故障现象与手动排错步骤见 [troubleshooting-error40.md](troubleshooting-error40.md)。

## 诊断要解决的问题

v0.1.4 之后暴露的主要问题不是垫片本身,而是故障归因。典型为 issue #2:报告者的症状由「卡 0%」变为「报 40」,整个 issue 中没有一份日志,现有信息不足以定位根因。

「错误 40」是通用失败码。COM 运行时缺失、注册与快照缺失、进程加固、目录权限、host-only 驱动未注册、host-only 绑定失效、适配器重名、UART 管道未建、嵌套后端 —— 至少九条互相独立的技术路径会产生同一现象。检查项罗列无法应对这种发散。

`环境检查.bat` 将该看的项固化为一次采集:执行一次,生成一份内容固定的报告。

## 修复分档

判据是无损性 —— 可撤销、不要求承担风险、不影响系统其他功能。这是设计立场,不是能力上限:可自动修复的项少于可检出的项,差额部分不是未实现,而是不应由本工具自动执行。

| 档 | 判据 | 处置 |
|---|---|---|
| **无损可修** | 可撤销、不影响系统其他功能 | 进执行范围,选中即执行 |
| **有损但必需** | 修复本身会中断其他功能 | 进执行范围,执行前明示影响并单独确认 |
| **有损且非必需** | 需重启、会连带影响其他功能 | 不执行,报告写明现状、原因与手动步骤 |

### 可修条目

共 7 项,id 可从报告第 [9] 节抄录。

```
  host-only 网络驱动 / 接口             <有损,执行前单独确认>
  host-only 网络绑定失效               <有损,执行前单独确认>
  Windows 性能计数器损坏               <无损>
  防火墙未放行 eNSP_VBoxServer         <无损>
  基础设备 VM 未注册 / 缺 _Link 快照   <须用启动 eNSP 的账户>
  eNSP 关闭后残留的 VirtualBox 进程    <有损,执行前单独确认>
  AR 模板显存被改小                    <会改写 eNSP 模板>
```

标签描述的是代价,不是档位。会中断网络或结束进程的标「有损」并要求单独确认;无中断风险但各有注意事项的(写入哪个账户的配置、是否改动 eNSP 文件)标签如实写明该注意事项。

- **无损可修** —— 防火墙放行 `eNSP_VBoxServer.exe`(规则可删除)、host-only 建接口与配置 IP、`lodctr` 重建性能计数器。

  > 防火墙项有两种失效形态,均会修复:无规则时新建;有规则但被禁用(或被设为"阻止")时,启用并规范该条规则本身,不在其旁新增同名规则。

- **有损但必需** —— 重装 host-only 驱动包并禁用/启用 host-only 网卡一次;仅执行禁用/启用重绑(不重装驱动包)的项同属此档;结束残留的 `VBoxHeadless` 进程同属此档。执行前明示:本机网络短暂中断(数秒至十几秒),运行中的设备、Tailscale / WireGuard 等常连隧道、Hyper-V 虚拟交换机均会闪断。选取与执行是两次输入。
- **需注意但不属有损** —— 重注册基础设备 VM(写入当前账户的 `VirtualBox.xml`,须用启动 eNSP 的账户执行);修改 `AR_Base.vbox` 的显存(写入 eNSP 安装目录下的文件,修改前备份)。两项同样单独确认。
- **有损且非必需** —— 关闭 Hyper-V / VBS / 内存完整性。不执行;报告仅写当前状态、原因,以及不建议关闭的理由。

### `hostonly-bind` 的判据

触发判据是日志中的 `VERR_INTNET_FLT_IF_NOT_FOUND`,不是绑定状态。绑定失效的特征是适配器存在且绑定项显示 `Enabled=True`,即读出的状态正常,失效的是其背后的数据路径;以绑定状态为判据无法检出。

该判据依赖日志解析。在此之前的版本中 `Repair-BounceAdapter` 已实现但无调用方。

### 安全属性

- 有损档的放行提示读取不到输入时,一律按不执行处理。判据是读到的值为 `$null`(EOF)而非空串(回车);`Read-Host` 无法区分两者,故使用 `[Console]::ReadLine()`。
- 选择中含未知 id 时一项都不执行,而非静默忽略。
- 每条实际执行的命令均回显,并写入 `<报告名>.repair.txt`。该工具会安装驱动、修改注册表、劫持 COM;仅记录「完成」无法事后核对,也无法转交他人复核。

## 诊断边界

报告不覆盖安装器自身的校验(由 `安装.bat` 核对)与设备包镜像的内容(不随本工具分发)。报告中没有报错,只说明已覆盖的项未发现问题,不等于环境无问题。

需对照实验才能区分的根因(例如「AR 报 40 但交换机正常」时,显存与模板路径两种成因需分别排除)诊断无法直接定论。

诊断会提示 eNSP 自身注册路径的缺陷(在 eNSP GUI 内注册设备会导致 eNSP 闪退,属设计结果,须改用 `注册设备.bat`),但不修复它。

两项设计为如实呈现、不作判定:

- host-only DHCP 的启用状态;
- 适配器名带 `#2` 后缀本身不判为故障,只报告「设备模板中的名称与实际接口名不一致」—— 致命的是不一致本身。

`vboxserver\` 写权限项读取 ACL,不执行实际写入。维持全程只读的承诺需要如此处理,代价是 deny 项与组的嵌套未按系统方式展开,结论偏保守:显示可写时基本确实可写,显示不可写时需用启动 eNSP 的账户复核。报告同时输出原始授权列表。

## 覆盖率

本版将调研得到的故障全集与诊断的实际检查项逐条对照:共 **33 条**,补充前完整覆盖 13 条(另 3 条部分覆盖),补充后 **21 条完整、3 条部分**。

这 33 条是**已知面**而非真实空间 —— `<VM>_Link` 快照一项不在其中,是从源码反推补入的。不将任何覆盖率读作"不会再遇到未见的故障"。

本工具不追求枚举所有根因,追求的是每次失败留下足够证据:报告中带完整的失败现场。

## 验证范围

判定规则由 `build/testdata\` 下的夹具驱动,共 **279 条**单元级断言覆盖。新增夹具含真机抓到的 `aborted` 状态、一份"实况与快照互相矛盾"的模板,以及两份日志的解析夹具。修复的每一步均带前置校验与 dry run 能力。

其中一部分是**接线断言** —— 探针已定义、`diag.ps1` 确实调用它、报告计算发现项的时机早于转录停止、安装器按档位分派而非执行全部项。此类断言缺失时,删除对应调用后其余测试仍全部通过,而功能已不存在。

修复路径已在一台机器上端到端走通,使用一次性制造的 4 处故障:防火墙禁用、基础设备 VM 取消注册、模板显存改小,以及一份含 `VERR_INTNET_FLT_IF_NOT_FOUND` 的日志。

- 其中三项实际执行成功并复验:防火墙、VM 注册、模板显存;
- 第四项(host-only 绑定重绑)仅走到确认环节 —— 执行它会导致本机断网数秒;
- 其余项(残留进程、性能计数器)未制造对应故障,仅在计划阶段验证。

「实际执行的命令进日志」由真机验证:临时禁用 `ensp_vboxserver` 防火墙规则后以 `-Fix firewall` 修复,`<报告名>.repair.txt` 中记录了 `Set-NetFirewallRule -DisplayName ensp_vboxserver ...`。「读取不到输入不执行」同样验证:以空输入运行 `-Fix hostonly-bind`,网卡未被修改。

**该验证在一台健康机器上人为制造故障,不在用户报障的真实环境上。** 报告结论以本机实际探测为准;机器发生真实故障时,先按报告与 `troubleshooting-error40.md` 给出的步骤判断。该工具的作用是省去对照文档查找命令,不替代判断。

## 附:交互界面已移除

修复不再使用交互界面。原实现(方向键 / Enter / 数字键 / 鼠标点击 / 面板重绘)共 1369 行,其中决定「修什么、怎么修」的为 389 行;可执行内容位于交互过程内,远程会话与无人值守无法使用。`tui.ps1` 与 `diag.ps1` 的渲染部分已删除。
