# v0.2 设计：环境诊断与 host-only 自愈

日期：2026-09-15
状态：待评审

---

## 1. 背景

v0.1.4-beta（2026-09-11 发布）打通了 USG6000V 的主链路。之后暴露的问题不是垫片本身，
而是**故障归因**：

- issue #2 中报告者从「卡 0%」变为「报 40」，但 issue 全程**没有一份日志**，
  现有信息无法定位根因。
- 2026-09-15 一次实测中，ARP 启动失败耗时数小时才定位到根因——VirtualBox 7.2 安装后
  **两个网络驱动组件（`VBoxNetAdp6` / `VBoxNetLwf`）都没有注册**，host-only 适配器
  根本不存在。该根因不在任何已发布版本中，既有文档的根因 D 也未覆盖。
- 面向公众的分发渠道（广然笔记 2026-09-15 的文章）分发的是 **v0.1.3**，
  即带有「卡 0%」静默假死缺陷的版本，会带来一批具有该症状的新报告。

与此同时，一次社区调研确认：**「错误 40」是多根因通用码**，至少 9 条互相独立的技术路径
（COM 运行时缺失、注册与快照缺失、进程加固、目录权限、host-only 驱动未注册、host-only 绑定失效、
适配器重名、UART 管道未建、嵌套后端）都会产生同一现象；而社区教程普遍把各自遇到的那一条
当作唯一根因。单纯的检查项罗列无法应对这种发散。

> 该调研的完整成果（含各条来源与可信度标注）作为工作材料另行保存，不随本仓库分发。

**v0.2 的目标因此不是修某一个 bug，而是让故障可归因。**

## 2. 范围

### 2.1 交付

1. **诊断能力**：分层的只读环境检查，输出可直接附进 issue 的报告。
2. **host-only 自检与修复**：覆盖「驱动未注册」这一新根因，并修复既有检查的漏检与误报。
3. **根因 D 文档拆分补深**：区分「绑定失效」与「驱动未注册」两种坏法。
4. **安装前检查**：把诊断前置到安装流程，让问题在安装阶段暴露而非设备启动时。

### 2.2 非目标（明确不做）

| 不做 | 理由 |
|---|---|
| 主动 `clonevm` + `startvm` 冒烟测试 | 网络设备启动需 30 秒–5 分钟（见调研 §4），任何短超时必然误报；克隆现有 VM 有选中用户正式 VM 的风险；清理失败会留下垃圾 VM |
| 自动修改网络配置以外的系统设置 | 关 Hyper-V / VBS / 内核隔离均为社区旧共识，且本项目已确认 Hyper-V 共存不是 error-40 成因 |
| 引入或镜像第三方检测工具的任何代码、文案、链接 | 见 §9 合规约束 |
| 打包或分发华为设备镜像 | 既有约束，不变 |

## 3. 架构

```
installer/
  checks.ps1          新增 — 检查原语，纯只读，返回对象，不打印不判断
  fix.ps1             新增 — 修复原语，每步带前置校验与 dryrun
  diag.ps1            新增 — 编排 checks.ps1，出报告，交互式修复菜单
  环境检查.bat        新增 — 双击入口（诊断 + 交互修复）
  install.ps1         改  — dot-source checks.ps1；移除内联的 Test-HostOnlyNetwork
  install_all.ps1     改  — 安装前调检查；加 -Check 转发
```

**职责边界**：

- `checks.ps1`：只探测事实，返回 `[pscustomobject]`。不做判断、不改系统、不打印。
- `fix.ps1`：只做修复，每步先校验前置条件，支持 `-DryRun`。不打印菜单。
- `diag.ps1`：唯一负责**判断、展示、交互**的一层。

三方共用同一份事实，避免检查逻辑在安装器和诊断之间漂移。

**约束（2026-09-15 实测更正）**：规则不是"必须 ASCII-only"，而是
**含非 ASCII 字面量的 `.ps1` 必须带 UTF-8 BOM**——PowerShell 5.1 只对**无 BOM** 文件
按 ANSI 解码。实测同一份含中文的脚本：带 BOM 输出正常，无 BOM 输出为乱码。

本仓库既有做法一致：`install.ps1` 等四个既有脚本**均带 BOM 且含大量中文**。

按文件定位：`checks.ps1` / `fix.ps1` / `build/tests/*.ps1` 为**无 BOM 纯 ASCII**（库与测试，
不面向用户）；`diag.ps1` 为 **UTF-8 带 BOM**（面向用户，需打印中文）。
`.bat` 侧用 `chcp 65001` 承载中文（既有做法）。

### 3.1 打包（新增，v0.2 起）

现状的发布包为**手工打包**，`Releases/` 下只有产物，无生成脚本。
`build/verify_zip_names.ps1` 是一次性校验，硬编码了单个版本路径且只验中文文件名。
本次新增 4 个文件后，手工打包会遗漏。

新增 `build/make_release.ps1`，职责：

1. 按**文件白名单**从 `installer/` 收集，而非全目录打包
2. **校验 `payload/` 下 DLL 的 SHA256 与 `install.ps1` 中常量一致**——
   此坑曾发生过：v0.1.3 重编译 `VBox52.dll` 后未同步 `$DLL_SHA256`，
   导致装机时报"哈希不符"并退出
3. 校验中文文件名在 zip 中未损坏（吸收现有 `verify_zip_names.ps1` 的逻辑）
4. 生成 zip 并输出其 SHA256，供 release notes 引用

### 3.2 升级路径

| 起点 | 路径 |
|---|---|
| v0.1.4-beta | 直接覆盖安装（文件级替换，无需先卸载） |

## 4. 诊断骨架：分层分流

调研确认了社区通行的分流判据，其价值在于**先用零成本事实缩小根因空间**，再谈具体检查项。
该判据成立的依据是 eNSP 设备存在三种后端：

| 后端 | 设备 | 受虚拟化/host-only 影响 |
|---|---|---|
| VBox 真客户机（克隆并启动） | AR 全系、WLAN 全系、USG6000V | 是 |
| VBox 真客户机（原地注册，不克隆） | CE6800/CE12800、CX200、NE40E/NE5000E/NE9000 | 部分 |
| 宿主侧原生进程（不走 VBox） | S5700/S3700/ROUTE/USG5500、PC、Hub、Client/Server、MCS、STA | 否 |

诊断按下列顺序分层，上层结论成立时下层不再展开：

```
Step 0  基础事实
        VBox 版本 / eNSP 版本 / 垫片 DLL 哈希 / OS build / 是否管理员

Step 1  分流 ①：宿主侧设备层是否可用
        ├─ 不可用 → eNSP 本体层
        │            lodctr 性能计数器 / 防火墙放行 eNSP_VBoxServer / 端口 54012-54014
        └─ 可用   → 继续
Step 2  分流 ②：AR 类报错但交换机与防火墙正常？
        ├─ 是 → AR_Base 模板层（Display VRAMSize / 模板路径 / 模板注册）
        └─ 否 → 继续
Step 3  分流 ③：CE/NE 类不可用但自带设备正常？
        ├─ 是 → 设备包与 eNSP 版本匹配层
        └─ 否 → 继续
Step 4  VirtualBox 层细查
        驱动完整性 → 适配器 → 绑定 → 数据路径 → 名字比对 → 注册与快照 → 权限
```

**Step 1 为只读**：宿主侧设备可经 `eNSP_Switch.exe sim` 安全调用，不涉及启动任何虚拟机。

## 6. host-only 六层检查

每一层都可独立判定，顺序即依赖顺序：

| 层 | 检查内容 | 判定依据 |
|---|---|---|
| 1 驱动 | `VBoxDrvInst.exe list` 含 `VBoxNetAdp6` 与 `VBoxNetLwf` | 2026-09-15 故障时两者皆无 |
| 2 服务 | `VBoxSup`/`VBoxNetAdp`/`VBoxNetLwf`/`VBoxUSBMon` 存在且 Running | `VBoxDrv` 在 7.2 上**本就缺席**，不可误判为缺失 |
| 3 VBox 视图 | `VBoxManage list hostonlyifs` 的名字、数量、IP | eNSP 按此视角绑定 |
| 4 Windows 视图 | `Get-NetAdapter` 按 `InterfaceDescription` 关联取连接名与 Status | 连接名是本地化字串（实测为「以太网 11」），**不可按名字匹配** |
| 5 绑定 | `Get-NetAdapterBinding -ComponentID oracle_VBoxNetLwf` 在**该适配器**上 Enabled | 该绑定同时存在于物理网卡与全部 Hyper-V vEthernet 上，非 host-only 专属 |
| 6 名字比对 | 模板 `.vbox` 的 `HostOnlyInterface name=` 与第 3 层实际接口名是否一致 | 这是 `#2` 问题的正确判据 |

**关于 `#2`**：`#2` 本身不必然致命。致命的是**模板中的名字与实际接口名不一致**。
社区做法（重建适配器后重新注册设备）之所以有效，是因为重新注册会重写模板中的名字。
因此诊断输出**只报不一致**，不把 `#2` 直接判为故障。

### 6.1 配套文档改动：根因 D 拆为 D1 / D2

`docs/troubleshooting-error40.md` 现有的根因 D 只描述了其中一种坏法，需拆分：

**D1 —— NDIS 过滤驱动绑定失效**

- 现象：`startvm` 报 `VERR_INTNET_FLT_IF_NOT_FOUND`
- 特征：**适配器存在且 Up、绑定项 Enabled=True、驱动服务正常**，仅绑定状态失效
- `VBoxDrvInst.exe list` 中**能找到** `VBoxNetAdp6` 与 `VBoxNetLwf`
- 修法：禁用 → 启用适配器；重启 `VBoxSVC` / `VBoxSDS`

**D2 —— host-only 驱动未注册**（2026-09-15 实测新增，现有文档未覆盖）

- 现象：同上，`VERR_INTNET_FLT_IF_NOT_FOUND` 或 `Could not find Host Interface Networking driver`
- 特征：**适配器根本不存在**，`hostonlyif create` 直接失败
- `VBoxDrvInst.exe list` 中**一个 VBox 包都没有**
- 修法：`VBoxDrvInst install`（netadp6）+ `netcfg -c s -i oracle_VBoxNetLwf`（netlwf）
  + **适配器禁用/启用循环** + 建接口与 IP/DHCP。**D1 的"禁用→启用"对 D2 无效**

**必须记录的陷阱（实测中最耗时的一点）**：

只补 `netadp6` 而不补 `netlwf` 时，`hostonlyif create` **会成功**，但接口名变成
`VirtualBox Host-Only Ethernet Adapter #2`。而 eNSP 模板按精确名绑定，于是症状与
驱动完全缺失时**一模一样**——错误 3 顶上来，表现仍是 error 40，极易误判为"修了没用"。

文档需给出三条报错随修复推进逐个消失的顺序，作为进度标尺：

| 顺序 | 报错 | 消失时机 |
|---|---|---|
| 1 | `hostonlyif create: Could not find Host Interface Networking driver!` | 补 netadp6 后 |
| 2 | VBoxSVC `HostWrap: ... could not be found` | 补 netadp6 后 |
| 3 | `VERR_INTNET_FLT_IF_NOT_FOUND` | **完成第 ③ 步（适配器重绑）后** |

**两件不要混为一谈的事**（此前本文档与 §7.2 曾互相矛盾，2026-09-16 更正）：

| 现象 | 在哪一步消失 |
|---|---|
| 接口名带 `#2` 后缀 | **第 ② 步**（补 netlwf）之后自行恢复干净 |
| 错误 3 `VERR_INTNET_FLT_IF_NOT_FOUND` | **第 ③ 步**（禁用→启用重绑）之后 |

即：补完 `netlwf` 后绑定会显示 `Enabled=True`、接口名也变干净，**但 `startvm` 仍会失败**——
过滤驱动尚未进入数据路径。这一步最容易被跳过，且跳过后的症状与完全没修**一模一样**。

## 7. 修复：交互式菜单

`环境检查.bat` 完成诊断后，列出发现的问题并进入交互选择：

```
发现 3 个问题：

  [1] host-only 网络驱动未注册    （会导致设备无法回连宿主）
  [2] 性能计数器损坏              （会导致设备一直输出 ####）
  [3] 防火墙未放行 eNSP_VBoxServer

  输入编号修复，多项用逗号分隔（如 1,3）；[A] 全部修复；[0] 退出：
```

**约束**：

1. 修复前必须确认 eNSP 已关闭（检查 `eNSP.exe` / `eNSP_VBoxServer.exe` 进程）。
   网络组件重绑会中断正在运行的设备。
2. 每项修复单独成步，逐步确认，可中途放弃。
3. 破坏性动作（重绑网络、删除适配器）执行前显示将要执行的命令。
4. 修复需管理员权限，未提权时提示并可选提权重跑。

### 7.1 修复准则：无损才修

修复项分三档，判据是**是否无损**（可撤销、不要求用户承担风险、不影响系统其他功能）：

| 档 | 处置 | 例 |
|---|---|---|
| **无损可修** | 进菜单，可自动执行 | 防火墙放行规则（加规则可删）、host-only 建接口/配 IP、`lodctr` 重建计数器 |
| **有损但必需** | 进菜单，执行前**明示影响**并单独确认 | host-only 驱动重装 + 适配器重绑（会短暂断网，Tailscale / Hyper-V vSwitch 会闪断） |
| **有损且非必需** | **不修**，只在报告里写明原因与手动步骤 | 关闭 Hyper-V / VBS / 内核隔离（需重启、影响其他功能） |

第三档的典型是虚拟化冲突类：报告应写明**当前状态**（例如"Hyper-V 在运行 → VBox 走 WHP
后端 → 设备启动需 3–5 分钟属正常，**不是故障，无需关闭**"），而不是给出关闭建议。
社区中大量"关 Hyper-V"教程针对的是 VirtualBox 5.2，与本项目场景相反。

### 7.2 host-only 修复顺序

依赖顺序不可调换：

```
① VBoxDrvInst.exe install --inf-file ...\netadp6\VBoxNetAdp6.inf
② netcfg.exe -v -l ...\netlwf\VBoxNetLwf.inf -c s -i oracle_VBoxNetLwf
③ Disable-NetAdapter / Enable-NetAdapter  （让过滤驱动进入数据路径）
④ hostonlyif create + ipconfig + dhcpserver
```

第 ③ 步最易漏：只做 ①② 时绑定显示 Enabled=True，但 `startvm` 仍报
`VERR_INTNET_FLT_IF_NOT_FOUND`，症状不变，极易误判为「修了没用」。

第 ② 步会短暂重绑网络组件（Tailscale / Hyper-V vSwitch 会闪断），故前置校验 eNSP 已关闭。

## 8. 报告形态

### 8.1 安装前检查

`install_all.ps1` 在段 1（提权安装）之前执行一次快速检查。检查范围为**穷举的固定集合**，
不含启发式判断：

| 项 | 判为阻断的条件 |
|---|---|
| host-only 驱动 | `VBoxNetAdp6` 或 `VBoxNetLwf` 任一缺失（§6 第 1 层） |
| VBox 可定位 | 找不到 VBox 安装目录 |
| eNSP 可定位 | 找不到 eNSP 安装目录 |
| 目标目录可写 | eNSP 目录无写权限 |
| VBox 主版本 | 主版本 < 7（垫片面向 7.x） |

其余检查项（性能计数器、防火墙、端口、抓包驱动等）**不进入安装前检查**，
仅由独立的环境检查承担——它们不阻断安装，在安装阶段报出只会造成噪音。

发现问题时给出三个选项：修复后继续 / 仍要继续 / 退出。

理由：v0.1.4 的经验是问题在设备启动阶段才暴露，而那时用户已经装完并认为成功了。

### 8.2 独立报告

`环境检查.bat` 输出：

- 终端分段展示（按 §4 的分层）
- 落一份文件：`%ProgramData%\ensp-vbox-shim\diag-<yyyyMMdd-HHmmss>.txt`

**日志采集规则**：只取**当前**日志文件并做**尾部截断**。

| 来源 | 用途 |
|---|---|
| `%ProgramData%\ensp-vbox-shim\install.log` | 安装过程 |
| `%ProgramData%\ensp-vbox-shim\vbox52_proxy.log` | 垫片调用链 |
| `%ProgramData%\ensp-vbox-shim\vboxmanage_wrapper.log` | VBoxManage 拦截记录 |
| `%USERPROFILE%\.VirtualBox\VBoxSVC.log` | VBox 服务侧（本次故障的关键证据源） |
| `<eNSP>\vboxserver\log\VBoxManage.log` | eNSP 自身命令日志（`VERR_INTNET_FLT_IF_NOT_FOUND` 出现在此） |
| `<eNSP>\vboxserver\log\install.log` | eNSP 安装记录 |

`ensp-vbox-shim\` 目录存在大量历史 `.bak_*` 文件，**不得全量打包**。

### 8.3 隐私

报告中不含用户名以外的个人信息。`VBoxSVC.log` 可能包含 VM 名称与路径，
在报告开头显式提示这一点。

## 10. 待核实项

以下三项必须实测确定，不得靠推理写入实现：

1. **VBox host-only DHCP 是否应启用**。社区资料称"启用服务器"应不勾选；
   本项目 installer 主动创建并启用了 DHCP。两者场景不同（5.2 与 7.2），需实测。
   **未定前的处理**：报告只**如实呈现** DHCP 的启用状态与作用域，不判定对错。
   注意这与 §5.2 中「修正 DHCP 判定」是两件事——后者修的是
   `NetworkName` 与接口名的**匹配方式**（`#N` 后缀导致误报），与是否启用无关。
2. ~~**VBox 7.2.14 与 7.2.16 是否存在与虚拟机启动相关的差异**~~
   **已核实，结论：无差异。** 逐行核对官方 changelog，7.2.14→7.2.16 在
   VMM / Networking / Storage / UART / Hardening 五类上的条目数为 1/0/0/0/0
   （7.2.14 那条是 `xcr0`/`xsave` 修复，属改进而非回归），
   7.2.16 在这五类上为 0 条。故报告**不得**以 VBox 小版本号作为诊断依据。
3. **`#2` 适配器经"重新注册设备"后是否确实可用**。既有项目记录与社区做法存在分歧。
   **未定前的处理**：按 §6 只报名字不一致，不判定 `#2` 本身为故障。

## 11.5 交互界面（2026-09-16 追加）

### 范围

**只有修复菜单变成 TUI**。诊断输出仍为顺序打印——报告文件与屏幕内容保持一致，
既可截屏也可直接附进 issue；把整段报告也 TUI 化会让两者分叉，需各维护一套。

### 技术约束（Windows 控制台，实测与已知）

| 项 | 事实 |
|---|---|
| 鼠标点击 | 必须开 `ENABLE_MOUSE_INPUT` 且**关闭** `ENABLE_QUICK_EDIT_MODE`——快速编辑开着时点击被拖拽选字吃掉，程序收不到事件 |
| 关快速编辑的代价 | 该窗口内**不能拖拽选字复制**，退出时还原。影响有限：报告本身是文件，不依赖从屏幕抄录 |
| 非真实控制台 | stdin 被重定向时 `GetConsoleMode` 直接失败（实测 `ERROR_INVALID_HANDLE`）。**必须有降级路径**，否则在管道/部分远程控制台里菜单直接不可用 |
| 绘制字符 | 制表符依赖 TrueType 字体；`.bat` 已设 `chcp 936`，默认字体下可用，但不保证所有机器 |

### 行为约定

启动时探测控制台能力：

- 能拿到控制台句柄 → 开鼠标输入（并关快速编辑），启用点击与滚轮
- 拿不到（重定向 / 非交互）→ **纯键盘**，且不尝试修改控制台模式

**键盘始终完整可用**，不依赖探测结果：`↑↓` 移动、`Enter` 确认、`Esc`/`0` 退出、
数字键直选、`A` 全选。鼠标是叠加能力，不是前提。

### 文件划分

| 文件 | 编码 | 职责 |
|---|---|---|
| `installer/tui.ps1` | 纯 ASCII、无 BOM | **机制**：控制台能力探测、模式开关与还原、按键/鼠标事件读取、绘制原语。**不含任何界面文案** |
| `installer/diag.ps1` | UTF-8 带 BOM | **内容**：菜单项文本、分档说明、确认话术 |

文案与机制分离是刻意的：`tui.ps1` 要能保持 ASCII（库的既有约定），而菜单文本是中文。

### 降级必须是显式的

探测失败时**告知用户当前是纯键盘模式**，而不是默默吃掉点击——否则用户会以为程序坏了。

## 13. 调研确证的事实更正

以下四项在本次调研中被证实或证伪，与项目既有表述有出入。实现时应以本节为准，
相关措辞在后续文档中一并更正。

1. **IntNet 在 Windows 上无架构变化**。7.x 的 `VBoxIntNetSwitch` 独立进程在非 Darwin
   平台**默认不编译**（源码注释：local IPC 实现 "experimental and intentionally
   disabled by default"）。7.0.0 changelog 中"移除 Internal Networking"一条属
   **macOS 主机**条目。因此 Windows 主机上不支持"7.x 改了 IntNet 实现导致丢帧"的推断。

2. **UART 默认值的准确表述**。VBox 默认**一个串口都不启用**（`GuestOSType` 的
   `mNumSerialEnabled` 构造默认为 0），并非 7.2 新引入的开关。
   7.2 changelog 中**没有任何** UART/串口默认值变更条目。
   v0.1.4 修复（补 `--uart2 0x2f8 3`）本身正确，但归因表述应据此修正。

3. **NDIS 过滤驱动改名早于 5.2**。`sun_VBoxNetFlt` → `oracle_VBoxNetLwf` 的改动
   提交于 2014-11-13（r96900），落在 5.0 开发周期内。因此
   **"5.2 用 NetFlt、7.x 用 NetLwf"这一前提不成立**。

4. **`IVirtualBox` 的父接口无官方文字来源**。项目内"IDispatch 插入使所有方法偏移 +4"
   的断言，在官方 SDK 参考页上**只有继承关系图（图片），正文无文字声明**。
   该结论目前仅由本项目的实测与补丁验证支撑，措辞中不应表述为官方事实。
