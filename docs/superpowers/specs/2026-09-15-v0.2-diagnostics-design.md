# v0.2 设计：环境诊断与 host-only 自愈

日期：2026-09-15
状态：待评审

---

## 1. 背景

v0.1.4-beta（2026-09-11 发布）打通了 USG6000V 的主链路。之后暴露的问题不是垫片本身，
而是**故障归因**：

- issue #2 中报告者从「卡 0%」变为「报 40」，但 issue 全程**没有一份日志**，
  现有信息无法定位根因。
- 2026-09-15 一次实测中，ARP 启动失败耗时数小时才定位到根因——VirtualBox 7.2 安装后
  **两个网络驱动组件（`VBoxNetAdp6` / `VBoxNetLwf`）都没有注册**，host-only 适配器
  根本不存在。该根因不在任何已发布版本中，既有文档的根因 D 也未覆盖。
- 面向公众的分发渠道（广然笔记 2026-09-15 的文章）分发的是 **v0.1.3**，
  即带有「卡 0%」静默假死缺陷的版本，会带来一批具有该症状的新报告。

与此同时，一次社区调研确认：**「错误 40」是多根因通用码**，至少 9 条互相独立的技术路径
（COM 运行时缺失、注册与快照缺失、进程加固、目录权限、host-only 驱动未注册、host-only 绑定失效、
适配器重名、UART 管道未建、嵌套后端）都会产生同一现象；而社区教程普遍把各自遇到的那一条
当作唯一根因。单纯的检查项罗列无法应对这种发散。

> 该调研的完整成果（含各条来源与可信度标注）作为工作材料另行保存，不随本仓库分发。

**v0.2 的目标因此不是修某一个 bug，而是让故障可归因。**

## 2. 范围

### 2.1 交付

1. **诊断能力**：分层的只读环境检查，输出可直接附进 issue 的报告。
2. **host-only 自检与修复**：覆盖「驱动未注册」这一新根因，并修复既有检查的漏检与误报。
3. **根因 D 文档拆分补深**：区分「绑定失效」与「驱动未注册」两种坏法。
4. **安装前检查**：把诊断前置到安装流程，让问题在安装阶段暴露而非设备启动时。

### 2.2 非目标（明确不做）

| 不做 | 理由 |
|---|---|
| 主动 `clonevm` + `startvm` 冒烟测试 | 网络设备启动需 30 秒–5 分钟（见调研 §4），任何短超时必然误报；克隆现有 VM 有选中用户正式 VM 的风险；清理失败会留下垃圾 VM |
| 自动修改网络配置以外的系统设置 | 关 Hyper-V / VBS / 内核隔离均为社区旧共识，且本项目已确认 Hyper-V 共存不是 error-40 成因 |
| 引入或镜像第三方检测工具的任何代码、文案、链接 | 见 §9 合规约束 |
| 打包或分发华为设备镜像 | 既有约束，不变 |

## 3. 架构

```
installer/
  checks.ps1          新增 — 检查原语，纯只读，返回对象，不打印不判断
  fix.ps1             新增 — 修复原语，每步带前置校验与 dryrun
  diag.ps1            新增 — 编排 checks.ps1，出报告，交互式修复菜单
  环境检查.bat        新增 — 双击入口（诊断 + 交互修复）
  install.ps1         改  — dot-source checks.ps1；移除内联的 Test-HostOnlyNetwork
  install_all.ps1     改  — 安装前调检查；加 -Check 转发
```

**职责边界**：

- `checks.ps1`：只探测事实，返回 `[pscustomobject]`。不做判断、不改系统、不打印。
- `fix.ps1`：只做修复，每步先校验前置条件，支持 `-DryRun`。不打印菜单。
- `diag.ps1`：唯一负责**判断、展示、交互**的一层。

三方共用同一份事实，避免检查逻辑在安装器和诊断之间漂移。

**约束**：所有 `.ps1` 必须保持 **ASCII-only**（PowerShell 5.1 按 ANSI 读取无 BOM 文件，
中文字面量会导致解析失败）。中文输出走 `\u` 转义或由 `.bat` 侧承载。

## 4. 诊断骨架：分层分流

调研确认了社区通行的分流判据，其价值在于**先用零成本事实缩小根因空间**，再谈具体检查项。
该判据成立的依据是 eNSP 设备存在三种后端：

| 后端 | 设备 | 受虚拟化/host-only 影响 |
|---|---|---|
| VBox 真客户机（克隆并启动） | AR 全系、WLAN 全系、USG6000V | 是 |
| VBox 真客户机（原地注册，不克隆） | CE6800/CE12800、CX200、NE40E/NE5000E/NE9000 | 部分 |
| 宿主侧原生进程（不走 VBox） | S5700/S3700/ROUTE/USG5500、PC、Hub、Client/Server、MCS、STA | 否 |

诊断按下列顺序分层，上层结论成立时下层不再展开：

```
Step 0  基础事实
        VBox 版本 / eNSP 版本 / 垫片 DLL 哈希 / OS build / 是否管理员

Step 1  分流 ①：宿主侧设备层是否可用
        ├─ 不可用 → eNSP 本体层
        │            lodctr 性能计数器 / 防火墙放行 eNSP_VBoxServer / 端口 54012-54014
        └─ 可用   → 继续
Step 2  分流 ②：AR 类报错但交换机与防火墙正常？
        ├─ 是 → AR_Base 模板层（Display VRAMSize / 模板路径 / 模板注册）
        └─ 否 → 继续
Step 3  分流 ③：CE/NE 类不可用但自带设备正常？
        ├─ 是 → 设备包与 eNSP 版本匹配层
        └─ 否 → 继续
Step 4  VirtualBox 层细查
        驱动完整性 → 适配器 → 绑定 → 数据路径 → 名字比对 → 注册与快照 → 权限
```

**Step 1 为只读**：宿主侧设备可经 `eNSP_Switch.exe sim` 安全调用，不涉及启动任何虚拟机。

## 5. 检查原语清单

### 5.1 新增（当前完全未覆盖）

| 检查 | 方法 | 依据 |
|---|---|---|
| 性能计数器 | `lodctr` 状态 / 查询计数器注册表可用性 | 华为 FAQ：计数器损坏导致设备一直 `####` |
| 防火墙放行 | `Get-NetFirewallApplicationFilter` / 规则查 `eNSP_VBoxServer.exe` | 华为 FAQ：同一症状 |
| 56 网段冲突 | `Get-NetIPAddress` 中 192.168.56.0/24 的接口数；`arp -a` 同 IP 多 MAC | VPN / VMware VMnet 冲突 |
| VBoxSup 服务 | 服务存在性与状态 | 对应 `supR3HardenedWinReSpawn` |
| 网卡属性 | `Get-NetAdapterBinding` 的 NDIS6 组件；适配器 IPv6 绑定 | 社区共识 |
| eNSP 端口 | 54012/54013/54014 是否被占用 | 华为 FAQ |
| eNSP 版本×设备 | eNSP 版本区间 与 `plugin\` 下存在的设备目录 | CE/NE/CX 需 ≥1.3.00.100；CX200/NE5000E 需 ≤1.2.00.390 |
| VRAMSize | 读模板 `.vbox` 的 `Display VRAMSize` | 出厂为 1 时会单独让 AR 失败 |
| 抓包驱动 | 区分 WinPcap 4.1.x 与 Npcap | eNSP 不认 Npcap 兼容层 |

### 5.2 修正既有

| 现状 | 问题 | 改为 |
|---|---|---|
| 只查 `VBoxManage list hostonlyifs` | 漏检驱动是否注册 | 增加 `VBoxDrvInst.exe list` 中 `VBoxNetAdp6`/`VBoxNetLwf` 的存在性 |
| DHCP 判定用精确名 `-eq "HostInterfaceNetworking-VirtualBox Host-Only Ethernet Adapter"` | 接口带 `#N` 后缀时误报 | 规范化后比较 |
| 名字检查用 `-like "…Adapter*"` | 通配符把 `#2` 也算作标准名，漏检 | 改为与模板 `.vbox` 中 `HostOnlyInterface name=` 做**实际比对** |
| 用 `Get-WindowsOptionalFeature -Online` | 需要管理员，未提权时静默失败 | 改用 `Win32_ComputerSystem.HypervisorPresent`（免提权，已实测） |

## 6. host-only 六层检查

每一层都可独立判定，顺序即依赖顺序：

| 层 | 检查内容 | 判定依据 |
|---|---|---|
| 1 驱动 | `VBoxDrvInst.exe list` 含 `VBoxNetAdp6` 与 `VBoxNetLwf` | 2026-09-15 故障时两者皆无 |
| 2 服务 | `VBoxSup`/`VBoxNetAdp`/`VBoxNetLwf`/`VBoxUSBMon` 存在且 Running | `VBoxDrv` 在 7.2 上**本就缺席**，不可误判为缺失 |
| 3 VBox 视图 | `VBoxManage list hostonlyifs` 的名字、数量、IP | eNSP 按此视角绑定 |
| 4 Windows 视图 | `Get-NetAdapter` 按 `InterfaceDescription` 关联取连接名与 Status | 连接名是本地化字串（实测为「以太网 11」），**不可按名字匹配** |
| 5 绑定 | `Get-NetAdapterBinding -ComponentID oracle_VBoxNetLwf` 在**该适配器**上 Enabled | 该绑定同时存在于物理网卡与全部 Hyper-V vEthernet 上，非 host-only 专属 |
| 6 名字比对 | 模板 `.vbox` 的 `HostOnlyInterface name=` 与第 3 层实际接口名是否一致 | 这是 `#2` 问题的正确判据 |

**关于 `#2`**：`#2` 本身不必然致命。致命的是**模板中的名字与实际接口名不一致**。
社区做法（重建适配器后重新注册设备）之所以有效，是因为重新注册会重写模板中的名字。
因此诊断输出**只报不一致**，不把 `#2` 直接判为故障。

## 7. 修复：交互式菜单

`环境检查.bat` 完成诊断后，列出发现的问题并进入交互选择：

```
发现 3 个问题：

  [1] host-only 网络驱动未注册    （会导致设备无法回连宿主）
  [2] 性能计数器损坏              （会导致设备一直输出 ####）
  [3] 防火墙未放行 eNSP_VBoxServer

  输入编号修复，多项用逗号分隔（如 1,3）；[A] 全部修复；[0] 退出：
```

**约束**：

1. 修复前必须确认 eNSP 已关闭（检查 `eNSP.exe` / `eNSP_VBoxServer.exe` 进程）。
   网络组件重绑会中断正在运行的设备。
2. 每项修复单独成步，逐步确认，可中途放弃。
3. 破坏性动作（重绑网络、删除适配器）执行前显示将要执行的命令。
4. 修复需管理员权限，未提权时提示并可选提权重跑。

### 7.1 host-only 修复顺序

依赖顺序不可调换：

```
① VBoxDrvInst.exe install --inf-file ...\netadp6\VBoxNetAdp6.inf
② netcfg.exe -v -l ...\netlwf\VBoxNetLwf.inf -c s -i oracle_VBoxNetLwf
③ Disable-NetAdapter / Enable-NetAdapter  （让过滤驱动进入数据路径）
④ hostonlyif create + ipconfig + dhcpserver
```

第 ③ 步最易漏：只做 ①② 时绑定显示 Enabled=True，但 `startvm` 仍报
`VERR_INTNET_FLT_IF_NOT_FOUND`，症状不变，极易误判为「修了没用」。

第 ② 步会短暂重绑网络组件（Tailscale / Hyper-V vSwitch 会闪断），故前置校验 eNSP 已关闭。

## 8. 报告形态

### 8.1 安装前检查

`install_all.ps1` 在段 1（提权安装）之前执行一次快速检查。检查范围为**穷举的固定集合**，
不含启发式判断：

| 项 | 判为阻断的条件 |
|---|---|
| host-only 驱动 | `VBoxNetAdp6` 或 `VBoxNetLwf` 任一缺失（§6 第 1 层） |
| VBox 可定位 | 找不到 VBox 安装目录 |
| eNSP 可定位 | 找不到 eNSP 安装目录 |
| 目标目录可写 | eNSP 目录无写权限 |
| VBox 主版本 | 主版本 < 7（垫片面向 7.x） |

其余检查项（性能计数器、防火墙、端口、抓包驱动等）**不进入安装前检查**，
仅由独立的环境检查承担——它们不阻断安装，在安装阶段报出只会造成噪音。

发现问题时给出三个选项：修复后继续 / 仍要继续 / 退出。

理由：v0.1.4 的经验是问题在设备启动阶段才暴露，而那时用户已经装完并认为成功了。

### 8.2 独立报告

`环境检查.bat` 输出：

- 终端分段展示（按 §4 的分层）
- 落一份文件：`%ProgramData%\ensp-vbox-shim\diag-<yyyyMMdd-HHmmss>.txt`

**日志采集规则**：只取**当前**日志文件并做**尾部截断**。

| 来源 | 用途 |
|---|---|
| `%ProgramData%\ensp-vbox-shim\install.log` | 安装过程 |
| `%ProgramData%\ensp-vbox-shim\vbox52_proxy.log` | 垫片调用链 |
| `%ProgramData%\ensp-vbox-shim\vboxmanage_wrapper.log` | VBoxManage 拦截记录 |
| `%USERPROFILE%\.VirtualBox\VBoxSVC.log` | VBox 服务侧（本次故障的关键证据源） |
| `<eNSP>\vboxserver\log\VBoxManage.log` | eNSP 自身命令日志（`VERR_INTNET_FLT_IF_NOT_FOUND` 出现在此） |
| `<eNSP>\vboxserver\log\install.log` | eNSP 安装记录 |

`ensp-vbox-shim\` 目录存在大量历史 `.bak_*` 文件，**不得全量打包**。

### 8.3 隐私

报告中不含用户名以外的个人信息。`VBoxSVC.log` 可能包含 VM 名称与路径，
在报告开头显式提示这一点。

- 不捆绑第三方环境检查 exe。

## 10. 待核实项

以下三项必须实测确定，不得靠推理写入实现：

1. **VBox host-only DHCP 是否应启用**。社区资料称"启用服务器"应不勾选；
   本项目 installer 主动创建并启用了 DHCP。两者场景不同（5.2 与 7.2），需实测。
   **未定前的处理**：报告只**如实呈现** DHCP 的启用状态与作用域，不判定对错。
   注意这与 §5.2 中「修正 DHCP 判定」是两件事——后者修的是
   `NetworkName` 与接口名的**匹配方式**（`#N` 后缀导致误报），与是否启用无关。
2. **VBox 7.2.14 与 7.2.16 是否存在与虚拟机启动相关的差异**。
   多个 issue 报告者使用 7.2.14，本项目开发机为 7.2.16。
   **未定前的处理**：报告仅记录实际检测到的 VBox 版本，不基于版本号给出任何推断。
3. **`#2` 适配器经"重新注册设备"后是否确实可用**。既有项目记录与社区做法存在分歧。
   **未定前的处理**：按 §6 只报名字不一致，不判定 `#2` 本身为故障。

## 11. 验收标准

1. 在 2026-09-15 故障机上复现：人为注销 `VBoxNetAdp`/`VBoxNetLwf` 后，诊断能
   **在第 1 层直接报出驱动缺失**，且报告内容足以判定根因。
2. 交互菜单可完成 host-only 四步修复。
   **验证方式为用户手动执行** `VBoxManage startvm` 并观察结果——
   工具本身不启动虚拟机（见 §2.2），此条是开发期的人工验收步骤，不是产品功能。
3. 诊断全程**不启动任何虚拟机**，不修改任何系统设置（只读路径）。
4. 报告文件可直接附进 issue，且体积可控、不含历史备份文件。
5. 安装前检查能捕获 §8.1 表中列出的五项阻断条件并给出修复选项，
   而非放行到设备启动阶段。
6. 在已正常工作的机器上运行诊断，**不产生任何改动、不报假阳性**。

## 12. 已知限制

- 诊断无法覆盖需要对照实验才能区分的根因（如「AR 报 40 但交换机正常」时，
  显存与模板路径两种成因需分别排除）。
- 不覆盖 eNSP 自身的注册路径缺陷（在 eNSP GUI 内注册设备会导致 eNSP 闪退，
  属设计结果，须改用 `注册设备.bat`）。诊断会对此给出提示，但不修复。
- 社区调研中关于 VirtualBox 7.x 行为变化的第三方转述未逐条复核，
  本设计不依赖该类条目。
